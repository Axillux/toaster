Toaster Docs

Getting started

  1. Add Toaster to your server.
  2. Give its role the permissions you want it to use (see What the bot needs).
  3. Run /settings and pick a punishment and a log channel.
  4. That's it. Every message with text or images is checked from now on.

How it works

Toaster reads every message in the servers it is in. Text and images are turned into vectors and compared against a scam database. On a match:

  1. The scam message is deleted immediately.
  2. The scammer gets a DM explaining what happened and why.
  3. The punishment from your /settings is applied.
  4. A deferred sweep removes every other message the account sent, in all channels and threads, and repeats until a full pass finds nothing left.

A meme database overrides scam matches on known-good images, so regular memes are not punished. One detection also punishes the account in every other server Toaster is in, using each server's own settings - unless the account is whitelisted there.

Commands

  • /help - DMs you the link to this documentation.
  • /userinfo [user] - account card: username, ID, creation and join dates, banner, full-size avatar.
  • /avatar [user] - full-size avatar (1024px, animated avatars stay animated).
  • /report [scope] - detections, deletions and punishments for this server, or globally with scope:global.
  • /about - what the bot is, live server and user counts.
  • /legal - Privacy Policy and Terms of Service links.
  • /ping - latency check.
  • /scan days:1-90 - clean up old scam (see /scan). Options: dry_run:True (report only, delete nothing), channel (scan one channel only). Manage Messages required.
  • /settings - the full configuration panel (see below). Manage Server required.
  • /rebuild - bot owner only. Commits reviewed images into the database and removes duplicates.

/settings

A Components V2 panel, split into two pages of three sections each, flipped with the arrow buttons at the bottom (the middle button shows the page number). Saving a value keeps you on the same page.

  • Language - English (default), Русский or Français. Translates the panel itself (including modals), the log cards, the /scan output, the DMs sent to punished users and the public commands. Outside servers the commands follow the invoker's client locale.
  • Scam Punishment - kick (default), mute or ban.
  • Punishment Duration - mute: timeout of 1-28 days (28 is Discord's hard cap). Ban: 0 = permanent, 1-28 = temporary ban the bot lifts when it expires. The section edits whichever duration the selected punishment uses; kick shows the mute one.
  • Log Channel - where scam alerts, scan progress and results are posted.
  • Honeypot - optional trap channel (see Honeypot). The bot keeps a warning message inside it; text and accent color are editable here.
  • DM Template - the card DM'd to the scammer. You edit the whole card, not just a line: markdown works (headings, bold, subtext), blank lines split the text into blocks separated by dividers, and a second field sets the card's accent color (hex like #ed4245, empty = the default red). Placeholders: {action}, {server}, {days}. Empty text = the localized default.
  • Whitelist - up to 25 users, 25 channels and 25 roles exempt from everything (see Whitelist).

The View Value button shows the current values of every setting at once. The bot never pings anyone: all mentions are rendered as plain text.

Whitelist

Whitelisted users, channels (their threads included) and roles are exempt from EVERYTHING the bot does in that server: live detection, /scan, scam-wave sweeps and cross-server punishment. The whitelist outranks an in-flight wave: whitelisting someone mid-wave stops the wave from growing and aborts the pending sweep (already-deleted messages and a landed punishment stay).

  • Each picker replaces its list; an empty selection clears it.
  • Entries for users who left or deleted channels/roles stay stored and apply again if the user rejoins, but they are no longer pre-selectable - saving a picker drops them.
  • Whitelisted members are also protected in other servers: a server where the user is whitelisted never punishes them for a detection that happened elsewhere.

Honeypot

A channel normal members should never see or post in (typically View Channel denied for @everyone). Anyone who posts there is treated as a scammer immediately: the message is deleted, the guild's punishment applies, and the wave sweep cleans up everything else they posted. No embedding check is involved, so it works instantly and even while the scam database is still building. Threads of the honeypot channel count too, and the whitelist outranks the honeypot as everywhere else. Disabled while no channel is selected.

The bot keeps exactly one warning message inside the honeypot channel: its text and accent color are editable in /settings (empty text = the localized default). It is edited in place when the text or the server language changes, moved when the channel changes, and deleted when the honeypot is disabled.

Warning: make sure normal members really cannot see the channel, or you will punish innocent people. If that happens, the False Positive button undoes what can be undone.

False Positive button

Every "Scam detected" card in the log channel carries a False Positive button (Manage Messages or Manage Server, or the bot admin). One click:

  1. Whitelists the author in this server - no checks, no sweeps, no punishment here anymore.
  2. Lifts the bot's own temporary ban and clears the timeout where still active. A kick cannot be undone.
  3. Queues the matched image into the pending meme list - after the owner's /rebuild the meme match outranks the scam match and the variant stops triggering in every server.

Deleted messages cannot be restored. The button works while the detection is kept (7 days by default); older detections can only be whitelisted via /settings.

Temporary bans

Discord's API has no native ban duration, so the bot lifts temporary bans itself: every scheduled unban is persisted and survives restarts (a ban that expired while the bot was down is lifted on the next startup). On expiry the ban is only lifted when it still carries the bot's own audit-log reason, so a manual re-ban is never undone by mistake. Every lifted ban is announced in the guild's log channel.

/scan

Walks channel history back up to 90 days and applies the same detection as live moderation. Progress is posted live to the log channel, including a direct link to every scam message the moment it is found. When it finishes, the same message becomes the summary: how many messages were checked, what was found, deleted, punished, and whether anything failed. Whitelisted channels are skipped whole; whitelisted users' and role members' messages are skipped.

  • By default it deletes found scam and punishes the senders (this guild only - live waves are the cross-server ones).
  • dry_run:True reports and sends review cards without deleting or punishing anything.
  • channel limits the scan to one channel. A channel on the whitelist is refused.
  • A Stop button halts the scan after the current message.
  • Detected scam variants are sent to the bot owner as review cards, oldest first.

Discord rate limits are handled automatically, so large scans simply take longer. Run with dry_run:True first to preview what would be deleted.

What the bot needs

  • Delete messages: Manage Messages, View Channel, Read Message History.
  • Kick: Kick Members.
  • Ban: Ban Members.
  • Mute: Moderate Members (Timeout Members).
  • Log channel: View Channel and Send Messages there.
  • The bot's role must be above the members it should punish. Server owners cannot be punished.

Review cards

Every detected scam is also sent to the owner as a card with the image and buttons: add to the scam database, add to the meme database, or ignore. Approved images are committed on /rebuild (which also removes near-duplicate images automatically). New variants approved this way improve detection for everyone. Server admins see every incident in their own log channel.

Notes

  • The bot never pings anyone. All mentions are rendered as plain text.
  • DMs are sent only to users who were punished, and one DM lists every other server that punished them.
  • Detection is probabilistic and can make mistakes. Check the log channel and use the False Positive button.
  • Direct messages are not moderated.
  • Everything works per server: punishment, whitelist, honeypot, language and DM template are each server's own choice.
